## Назначение

`store/` — клиентская витрина спортивного магазина Tatami. Каталог, корзина, оформление заказа, авторизация и история заказов работают локально, а при наличии `.env.local` подключаются к Supabase.

Основная демо-витрина: `Tatami` (`/tatami`). Демо-каталог использует UAH.

## Стек и запуск

- React 19 + TypeScript + React Router 7;

```bash
cd /Users/vsh/Projects/shop/store
```

```text
src/
  App.tsx                 маршруты

  types.ts                доменные типы

  context/
```

Глобальная композиция провайдеров: `AuthProvider` → `ToastProvider` → маршруты. Внутри маршрута магазина создаются `StoreProvider` и зависящий от него `CartProvider`.

## Маршруты

| URL | Экран / поведение |
| --- | --- |
| `/` | перенаправляет на `/tatami` |
| `/:storeSlug` | каталог магазина |
| `/:storeSlug/product/:productId` | карточка товара и добавление варианта в корзину |
| `/:storeSlug/cart` | корзина |
| `/:storeSlug/checkout` | гостевое или авторизованное оформление |
| `/:storeSlug/receipt/:code` | чек созданного заказа |
| `/:storeSlug/login`, `/:storeSlug/register` | вход и регистрация |
| `/:storeSlug/orders`, `/:storeSlug/account` | только для авторизованного пользователя |
| `/:storeSlug/admin` | CRM менеджера: заказы, статусы и остатки; доступ через Supabase RLS |
| `/q/:code` | short link: открывает привязанный товар |

Неизвестный магазин и несуществующие товары отображают понятные страницы-заглушки; fallback ведёт к Tatami.

## Данные и демо-сценарии

- В `mock/data.ts` определён один магазин: `Tatami`, slug `tatami`, ID `store_tatami`.
- В каталоге шесть активных товаров спортивной одежды и аксессуаров.
- Варианты товара могут быть со скидкой, ограниченным остатком или предзаказом.

- Short link `/q/hoodie24` ведёт на Training hoodie.

Цена варианта после скидки считается в `optionPrice`; отображение цены и даты — в `formatPrice` и `formatDate`.

## Где хранится состояние

Всё постоянное состояние хранится в браузерском `localStorage`; очищается вместе с данными сайта в браузере.

| Ключ | Содержимое |
| --- | --- |
| `shop.store.token` | моковый токен текущей сессии |
| `shop.store.users` | зарегистрированные пользователи с паролями в открытом виде |
| `shop.store.orders` | созданные заказы |
| `shop.store.cart.<storeId>` | корзина конкретного магазина |

Первый вызов авторизации создаёт демо-пользователя, если список пользователей ещё пуст. Моковый токен имеет формат `mock.<userId>` и не защищён криптографически.

## Поведение заказа

`api.createOrder` собирает строки заказа из корзины и статического каталога, применяет скидки и сохраняет заказ в `localStorage`. Оплата всегда имитируется: новый заказ получает `status: PAID` и `paymentStatus: MOCK_PAID`. Оформление доступно гостю; в таком случае `userId` — `guest`, и заказ не появится в разделе «Orders» авторизованного пользователя.

## Supabase

- `supabase/migrations/20261008000000_store_crm.sql` содержит схему каталога, заказов, CRM и RLS.
- `supabase/seed.sql` добавляет стартовый Tatami-каталог.
- `src/lib/api.ts` выбирает Supabase-адаптер, если заданы `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`; иначе сохраняется локальный mock-режим.
- Заказ в Supabase создаётся RPC-функцией, которая проверяет цену и остатки на сервере.

## Ограничения прототипа

- Для работы Supabase нужен созданный проект, применение миграции и публичные ключи в `.env.local`.
- В mock-режиме сохраняются старые ограничения `localStorage`: пароли и токены не защищены, а остатки не резервируются.
- Формы полного управления каталогом и клиентскими тегами пока ещё отсутствуют; CRM-экран покрывает заказы, статусы и остатки.
- Чек в Supabase доступен по случайному коду-квитанции; не публикуйте такие ссылки.
- Изображения товаров берутся с Unsplash по внешним URL.
